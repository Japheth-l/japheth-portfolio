# Portfolio — Japheth Mwinekpieng Lamuo

A server-rendered portfolio built as a single Node.js app: Express + EJS for the pages,
MongoDB for the content, and a JWT-protected admin panel for editing it.

## What's in it

**Frontend (server-rendered)**
- Express + EJS templates — the homepage is rendered from data in MongoDB, not hardcoded HTML
- Terminal panel that fetches this server's own `/api/me` and types out the real response
- Scroll-spy nav, reveal-on-scroll, reduced-motion support, skip link, 404/500 pages

**Backend**
- `GET  /api/projects` · `GET /api/projects/:id` — project data
- `GET  /api/content` · `GET /api/me` — site copy and profile JSON
- `POST /api/contact` — validated, rate-limited (5 / 15 min), stored in Mongo, emailed via Resend
- `POST /api/analytics/track` — first-party click tracking, no third-party scripts
- `GET  /health` — health check for Render

**Admin panel** (`/admin`, single account, bcrypt + JWT in an httpOnly cookie)
- Create / edit / delete projects
- Edit hero copy, about paragraphs, and the skills manifest
- Read and delete contact messages
- Page-view and outbound-click stats

**Security**
- `helmet` with a strict Content-Security-Policy — no `unsafe-inline`, so there
  are no inline scripts or event handlers anywhere in the templates
- HSTS and `secure` cookies in production; `SameSite=Lax` blocks cross-site CSRF
- Rate limits on every public write: contact (5 / 15 min), analytics (30 / min),
  admin login (10 / 15 min)
- Length caps in both the request validator and the schemas
- EJS escapes all stored content, so CMS input cannot inject markup

## Tests

```bash
npm test
```

20 tests over the API, admin auth, and security headers, using an in-memory
MongoDB. They set their own environment and never read `.env`, so they cannot
reach the live database.

## Running locally

```bash
npm install
cp .env.example .env
npm run dev
```

With `MONGODB_URI` left blank the app starts an in-memory MongoDB automatically and seeds
itself, so it runs with zero setup. Point `MONGODB_URI` at MongoDB Atlas when you want data
to persist. `npm run seed` resets the database to the starting content.

To use the admin panel locally, generate a password hash and put it in `.env`:

```bash
node -e "console.log(require('bcryptjs').hashSync('your-password', 10))"
```

## Deploying to Render

`render.yaml` is set up for a single free web service. Push this repo to GitHub, create a
Blueprint on Render pointing at it, then set these environment variables in the dashboard:

| Variable | Value |
| --- | --- |
| `MONGODB_URI` | MongoDB Atlas connection string |
| `RESEND_API_KEY` | From resend.com |
| `OWNER_EMAIL` | Where contact messages are delivered |
| `ADMIN_EMAIL` | Login email for `/admin` |
| `ADMIN_PASSWORD_HASH` | bcrypt hash generated with the command above |
| `JWT_SECRET` | Generated by Render automatically |

Set `NODE_ENV=production` (already in `render.yaml`) so cookies are marked `secure` and
static assets are cached.

Two things worth knowing about the free plan: the instance sleeps after inactivity, so the
first request after a quiet period takes a few seconds, and `MONGODB_URI` must point at
Atlas — the in-memory fallback is development-only and refuses to start in production.
